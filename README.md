# 接通就赢（Connect to Win）

一款 2D 电路旋转解谜小游戏：点击方块顺时针旋转 90°，把起点和终点接通，电流点亮终点即通关。

当前版本 **v0.2.0**，包含 30 个固定关卡、**精确最优解 + 三星评价**、**电流传播动画**、**闸刀开关**、每日挑战与**战绩卡分享**、本地进度、完整自动化测试（92 项），以及可直接导入微信开发者工具的微信小游戏构建产物。

> 说明：本项目未接入任何真实广告、支付或后端服务；未获得 AppID、版号、备案与流量主资格。相关事项见 [docs/publish-checklist.md](docs/publish-checklist.md)。

## 1. 技术选型说明（重要）

任务书建议使用 Cocos Creator。**当前机器未安装 Cocos Creator，也未安装微信开发者工具**（已检查 `C:\Program Files`、`%LOCALAPPDATA%\Programs`、`D:\` 等常见安装路径）。Cocos Creator 的安装包体积大、需要登录账号、命令行构建依赖编辑器与图形环境，在无人值守环境下不可靠。

因此本项目采用**等价的工程化方案**，并保持了任务书要求的全部模块职责划分：

| 需求 | 实现方式 |
| --- | --- |
| TypeScript | 全量 TypeScript，`strict` 模式，`tsc --noEmit` 零错误 |
| 2D 场景 / 节点 / 触摸 | 自研轻量 Canvas 2D 渲染层（`src/render/Renderer.ts`）+ 统一指针事件 |
| 微信小游戏构建目标 | `npm run build` 直接产出 `dist/wxgame/`（`game.js` / `game.json` / `project.config.json`） |
| 平台适配层 | `src/platform/`（Web / 微信双实现，业务层零平台判断） |
| 包体 | 微信主包 **88.8 KB**（上限 4 MB） |
| 运行依赖 | 0 个运行时依赖；素材全部为代码绘制矢量图形，无外部图片/音频 |

这样做的代价与边界（已如实记录）：

- 没有 Cocos 的可视化编辑器与场景文件，界面由布局函数 + Canvas 绘制生成；改版式需改代码。
- 没有使用 Cocos 的物理、动画系统，动画为手写的插值与粒子。
- **如果后续必须交付 Cocos 工程**：`src/core/`（棋盘、连通性、关卡、存档、每日挑战）与 `src/platform/` 是纯逻辑，可直接迁移；只需用 Cocos 的 `Component` + `Graphics`/`Sprite` 重写 `src/render/` 与输入绑定，预计改动集中在渲染层。

## 2. 快速开始

环境要求：Node.js ≥ 18（本机验证版本 v22.22.2），npm ≥ 9。

```bash
npm install            # 安装开发依赖（typescript + esbuild）
npm run dev            # 构建并启动本地预览 http://127.0.0.1:5173
npm test               # 构建 + 92 项自动化测试
npm run validate       # 独立关卡合法性校验程序
npm run build          # 产出 Web 预览版与微信小游戏包
```

常用命令一览：

| 命令 | 作用 |
| --- | --- |
| `npm run typecheck` | TypeScript 类型检查（`tsc --noEmit`） |
| `npm run levels` | 重新生成 30 个固定关卡到 `src/data/levels.json` |
| `npm run validate` | 校验全部关卡的合法性、难度曲线、每日挑战可复现性 |
| `npm test` | 构建 + 运行全部 92 项自动化测试 |
| `npm run build` | 构建 `dist/web` 与 `dist/wxgame`，并做包体检查 |
| `npm run dev` | 本地静态服务器（预览 `dist/web`） |

本地预览：`http://127.0.0.1:5173/`（正式预览页）、`http://127.0.0.1:5173/qa.html?s=win`（QA 场景页，可直接驱动到指定界面，仅用于开发验收）。

> **请通过 `npm run dev` 起本地服务器打开**，不要直接双击 `dist/web/index.html`：`file://` 协议下浏览器可能拦截脚本与本地存储，表现为白屏或无法存档。

微信小游戏：打开微信开发者工具 → 导入项目 → 目录选择 `dist/wxgame` → AppID 填自己的（当前为 `touristappid` 游客模式）。

## 4. 玩法规则

1. 棋盘为 `宽 × 高` 网格；每格可能是**电路方块**（起点、终点、管道、干扰块）或**空格**（不可放置）。
2. **点击**可旋转方块 → 顺时针旋转 90°（上→右→下→左→上）；**长按**（≥380ms）→ 逆时针 90°。
   两个方向都只算 1 步，转错了可以立刻转回来，不会因为一次误触废掉整局。
3. 两个相邻方块**互相开口朝向对方**才算连通；只有一侧开口不算。
4. 从起点出发做 BFS，只要能到达终点即通关 —— 判定只依赖真实连接关系，与点击次数、动画状态无关。
5. 步数：每次成功旋转 +1；旋转起点/终点/空格不计步，也不改变状态。
6. 失败：步数用尽（`已用步数 ≥ 上限`）且尚未接通。**最后一步刚好接通算赢**（先判胜再判负）。
7. 重试：棋盘旋转、步数、状态全部回到关卡初始值。
8. 提示：免费高亮参考解路径 2.6 秒，不消耗广告，不限制次数（仅统计次数）。
9. 分叉 / 死路 / 障碍：三通、四通方块允许存在，死路分支不会误判通关；空格视为障碍。

更详细的规则与关卡设计见 [docs/design.md](docs/design.md)。

## 5. 屏幕适配

界面按 **750 × 1240** 的逻辑尺寸布局，缩放策略是「取较小值 + 居中」：

```
scale = min(屏幕宽 / 750, 屏幕高 / 1240)
```

- **手机竖屏**（如 375×812）：按宽度缩放，铺满全屏，设计高度自动变高（1624）。
- **桌面浏览器 / 横屏 / 平板**（如 1280×800、1920×1080）：按高度缩放，内容居中成一条竖屏窗口，左右留白并暗化，**所有按钮都在可视区域内**。
- 点击坐标按同一套视口反算，宽屏留白不会导致「点不准」。

早期版本只按宽度缩放，在桌面窗口下设计高度被压到 469，首页内容会溢出并被裁切；该问题已修复，并有 10 种屏幕尺寸的自动化布局测试覆盖（320×568 ～ 1920×1080）。

## 6. 已实现功能

- 30 个固定关卡，逐关解锁；3×3 起步、后段到 8×8，最优步数 6→29，步数余量 +6→+2；起点/终点随机落在任意一边，干扰块几乎填满棋盘，13 关起出现闸刀开关。
- **精确最优解**：`OptimalSolver` 用 DFS + 分支限界求解，并通过「真实执行后是否通关」复核；生成关卡时强制「最优解不得明显短于设计路径」，杜绝捷径关。
- **三星评价**：3 星 = 达到最优步数，2 星 = 最优 + 20% 容错，1 星 = 完成；星级只升不降，可无限重玩刷星。
- **电流传播动画**：沿真实连通路径逐格流动，断路时停在断点闪橙色提示，通关时白闪 + 粒子；动画不影响判定与输入。
- **闸刀开关**：关闭时物理不导电，点击切换（1 步），纳入求解与校验，闭合/断开有明确几何差异。
- **每日挑战战绩卡**：本地绘制 750×1000 图片，Web 下载、微信调起分享菜单；不强制分享、不做排行榜。
- 每日挑战：以北京时间日期为种子确定性生成，同一日期所有玩家谜题一致；记录当天结果。
- 完整流程界面：启动页 → 关卡列表 → 游戏页 → 暂停/通关/失败弹窗 → 设置页；返回、重试、下一关、继续全部可用。
- 步数显示（当前 / 上限）、目标步数、最佳步数、通关反馈与解锁提示。
- 本地存档：最高解锁关卡、每关通关与最佳步数、每日挑战结果、音效设置、基础统计；损坏/旧版存档自动降级修复，读写失败不影响启动。
- 清除进度入口（二次确认）。
- 音效（程序化合成，可静音）、震动反馈、旋转动画、通关粒子。
- 微信适配：主画布、安全区、触摸、本地存储、前后台切换（切后台自动暂停）、分享、震动。
- 广告预留：激励视频（失败后可换 +3 步）、插屏（每 5 关一次，可关闭）；未配置广告位时进入**开发模式**，不展示任何广告、不发放奖励。
- 事件记录接口（AnalyticsAdapter），默认仅内存环形缓冲，不上报、不采集个人信息。
