## 2. 类目、备案与前置审批

小游戏上线需要两层备案，顺序不能颠倒：

1. **小游戏备案（前置审批）** —— 在「账号设置 → 小程序备案 → 去完善」中提交。
   - 有版号（IAP，含虚拟支付）：选择**情况一**，办结时限约 5~12 个工作日。
   - 无版号（IAA，无虚拟支付）：选择**情况二**，办结时限约 10~30 个工作日。
   - 平台初审约 1~2 个工作日，主管部门约 10~20 个工作日。
   - 提交内容：游戏名称、玩法/场景/功能说明、**与版本一致的截图**、适龄提示等。
2. **小程序备案（工信部）** —— 前置审批通过后提交，流程为：填写信息 → 平台初审 → 工信部短信核验 → 通管局审核 → 备案成功。

自查要点（官方常见驳回原因）：

- [ ] 游戏名称、账号主体在**全流程保持一致**；备案通过后改名/迁主体会触发重新备案。
- [ ] 游戏名称**不能与已获批游戏重名**（同名会被驳回，需改名重提）。
- [ ] 名称要与玩法有关联（例如本作「接通就赢」对应电路接通玩法，符合）。
- [ ] 截图尺寸、版本一致，且与提审版本内容一致。
- [ ] 适龄提示已设置且通过。
- [ ] 备案期间不要改名、不要主体迁移。

> 本项目当前状态：**未备案**，未提交任何材料。

- [ ] 若后续加入内购，必须补版号，并按「情况一」重新备案。

> 本项目当前状态：**无软著、无版号**。首版无内购，按 IAA 路线规划。

## 5. 隐私与未成年人保护

- [ ] 准备**隐私政策**页面（可访问的 URL），说明收集哪些数据、用途、存储位置、删除方式。
  - 本项目实际行为：**不收集任何个人信息**，进度仅存于本机 `wx.setStorageSync`，无网络上报。
  - 需在「小程序后台 → 设置 → 服务内容声明 → 用户隐私保护指引」中如实填写：本项目不涉及用户信息收集。
- [ ] 若后续接入统计 SDK、登录、支付，必须同步更新隐私政策并在后台声明。
- [ ] **未成年人保护**：按平台要求完成适龄提示；若涉及虚拟支付需接入实名认证与防沉迷。本项目无内购、无社交，仍应在备案时如实填写适龄提示（建议 8+ / 12+，以平台分级要求为准）。
- [ ] 不设置任何「看广告才能继续玩」的强制门槛（本项目提示免费、关卡失败可直接重试）。

## 6. 广告（流量主）资格

- [ ] 满足**流量主**开通条件后在后台申请（后台按累计独立访客等指标判定准入，具体门槛以「流量主」页面显示为准；公开资料常见说法为累计 UV 达到数百至上千，政策会调整，**不要照抄旧教程**）。
- [ ] 开通后在「流量主 → 广告管理 → 广告位管理」创建广告位，拿到 **adUnitId**。
- [ ] 把 ID 写入 `src/config.ts`：
  ```ts
  rewardedAdUnitId: 'adunit-xxxxxxxx',      // 激励视频
  interstitialAdUnitId: 'adunit-yyyyyyyy',  // 插屏（可选）
  enableInterstitial: true,
  ```
- [ ] 重新执行 `npm run build`，确认 `dist/wxgame/game.js` 中的广告位已更新。
- [ ] 广告合规自查：
  - 激励视频必须**用户主动触发**，看完才发奖励（本项目：失败弹窗中的「看视频 +3 步」，`onClose.isEnded === true` 才发放）；
  - 不得在点击/旋转/每次失败时弹广告（本项目：插屏最多每 5 关一次，且可关闭）；
  - 不得诱导点击、不得遮挡游戏操作区；
  - 广告加载失败要有降级（本项目：加载失败提示「广告未完整播放，未发放奖励」）。

> 本项目当前状态：**无流量主资格、无广告位 ID**，广告层处于开发模式（`DevAdsAdapter`），不会展示任何广告，也不会发放任何奖励。代码里不存在任何「模拟广告收益」的逻辑。

## 10. 审核被驳回后的处理流程

1. 在「小程序后台 → 版本管理 → 审核版本」查看驳回原因（站内信 + 审核详情）。
2. 按原因分类处理：
   - **资质/备案问题** → 回到「小程序备案」补齐材料，重新走前置审批。
   - **内容问题**（名称、图标、截图、文案） → 修改后重新上传版本。
   - **功能问题**（无法进入、按钮无响应、闪退） → 本地按驳回描述复现，修复后 `npm test` + 真机回归，再上传。
   - **广告问题**（诱导、强制观看、遮挡） → 调整广告触发点与频次，必要时先关闭广告再提审。
3. 修改后版本号递增（如 `0.1.1`），在「版本管理」重新提交审核。
4. 保留每次驳回记录与修复说明，避免同一问题反复出现。
5. 若对结果有异议，可通过后台「反馈」或开发者助手申诉，附上复现视频与说明。
