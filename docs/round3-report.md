日期：2026-10-29

### 1.2 发现的具体问题

1. **没有撤销**。玩家误点错方块（不是转错方向，而是点错格子）只能重试整关，代价过大。
2. **每日挑战只有一条记录**（`daily: {date, cleared, steps}`），没有连续天数、没有历史，缺少回访动力。
3. **切关卡时渲染状态不清理**：`Renderer` 的旋转动画（`anims`）、粒子（`particles`）、电流（`flow`）、
   闪光（`flash`）在切换关卡后仍保留，会按旧坐标画到新棋盘上——这是真实缺陷，不是理论风险。
4. **长按定时器在离开关卡时没取消**：`pointerDown` 启动的 380ms 计时器，如果玩家按住时点了返回，
   定时器仍会在新界面上触发一次操作。
5. **难度曲线只按「参考解步数」校验**，而玩家实际感受的是「最优步数」。实测 L15→L17 的最优步数
   19→15，明显回退，校验器没有报错。

## 三、新增与修复的功能

### 3.1 撤销（新增）

- 每关 3 次，回退上一步并**返还 1 步**；
- 支持回退旋转与开关状态；
- 通关后、无历史时、次数用尽时不可用（按钮置灰）；
- 重试恢复次数与历史；
- 不影响存档里的最佳步数与星级（撤销是局内行为）。

> 为什么限 3 次：无限撤销等于无限试错，三星就失去意义。

### 3.2 每日挑战连续记录（新增）

- `dailyStreak` / `bestDailyStreak` / `dailyHistory`（最近 30 天，按日期去重，保留更好成绩）；
- 连续判定基于「上一天是否也完成」，中断后从 1 重新开始；
- 同一天重复挑战不累加连续天数；
- 首页与通关弹窗都有展示。

### 3.3 状态清理（修复）

- 切关卡/切模式时清空渲染层所有瞬时状态，避免旧关卡的电流、粒子画到新棋盘；
- 离开关卡时取消长按定时器，避免「按着返回」导致新界面被误操作。

### 3.4 难度曲线校验（修复）

- 生成器约束：最优步数 `>= 上一关 - 1` 且 `<= 上一关 + 6`；
- 校验器同步检查，超出即失败并打印具体关卡号。

## 五、尚未解决的问题

1. **微信端未做真机验证**：本机没有微信开发者工具，微信包只经过「模拟 wx 环境」的冒烟测试。
   长按（`onTouchEnd`）、战绩卡（`canvasToTempFilePath`）、音频在不同机型上的表现均**未验证**。
2. **撤销与最优解的关系没有做数值平衡**：撤销返还步数，理论上玩家可以「撤销 → 换方向」来降低步数，
   但撤销次数限 3，影响有限；没有做量化验证。
3. **每日历史没有 UI 列表页**：数据已经存下来了，但只展示连续天数，没有「历史成绩」页面。
4. **关卡内容量仍然偏少**：30 关约 20 分钟，靠三星和每日挑战撑重复游玩。
5. **没有做性能采样**：只有 Web 端的主观观察，没有 `wx.getPerformance()` 数据。

## 七、下一轮最值得做的三项优化

1. **真机验证 + 性能采样**：装开发者工具，按上一节清单逐项过，采集启动耗时与帧率。
   这是目前最大的未知项——所有微信端结论都还停留在「模拟环境」。
2. **每日挑战历史页**：数据已经有了（`dailyHistory`），做一个简单的日历/列表页展示最近 30 天成绩，
   把「连续天数」变成可见的长期目标。
3. **内容扩充到 60 关并分章节**：求解器已能保证质量与难度曲线，扩量成本低；
   同时可以给后期章节引入第二个特殊组件（如单向阀），但一次只加一个。
